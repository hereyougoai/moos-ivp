## 一、 8/28 研發背景與重大里程碑總覽

本日研發聚焦於讓 **`m_shield_demo`（Shield AI 多無人船協同搜索、包夾與驅逐防衛系統）** 邁向具備**真實島嶼與複雜海岸地形感知（Land-Aware & Coastal Terrain Defense）** 的全新世代。

在開闊水域中，任務規劃器可假設任意方向皆可航行；但在真實近岸、海灣、島礁等複雜水域中，傳統演算法面臨三大致命瓶頸：
1. **規劃器「盲目鋪設站位與航線」**：搜索割草機航線與包夾阻擋點常被直接投影在陸地或岬角上，導致無人船在避障與導航行為間激烈衝突、原地卡死。
2. **目標逃逸扇區缺乏地形約束**：協調器未利用地形屏障，無法識別海灣與死胡同對目標逃逸路徑的天然封鎖。
3. **主機卡頓引發「物理穿牆穿島」（Sim Jump）**：當高負載導致模擬器暫停數秒後恢復時，單步積分時間驟增，導致無人艇直接瞬移穿透島嶼。

本日完成以下 **5 大核心技術模組研發與系統重構**：

1. **新增非凸多邊形地形引擎底層庫（`lib_landmodel`）**：
   - 建立高精度非凸多邊形射線交叉（Even-Odd Ray Crossing）演算法，克服原生 `XYPolygon` 無法處理凹多邊形與真實海岸線的限制。
2. **新增近岸安全守護與觸礁自救應用程式（`pLandGuard`）**：

   - 於 `USM_Model` 引入 `max_time_step` 防護，徹底杜絕主機延遲導致的穿島瞬移。
5. **複雜海岸任務環境生成器與自動化基準測試套件（`gen_land.py` / `bench_land_sweep.sh`）**：
   - 支援隨機與真實島礁地圖自動生成、凸多邊形分割及自動化多回合近岸防衛模擬評估。

## 三、 核心架構與演算法技術詳解

### 1. 地形引擎底層庫（`lib_landmodel`）之非凸幾何推導

#### 🛑 原生 `XYPolygon` 的缺陷
MOOS-IvP 內建之 `XYPolygon::contains()` 在多邊形為非凸（Non-convex，如凹海灣或彎曲島嶼）時直接強制返回 `false`。若直接用於海圖判定，會導致所有非凸海岸線被錯誤視為「無障礙水域」。

#### 💡 `LandModel` 的非凸射線法解決方案
`LandModel` 讀取 `land.txt` 中真實海岸輪廓頂點 $(P_0, P_1, \dots, P_{n-1})$，採用射線奇偶交會法（Even-Odd Ray Casting）：
1. **點包含判定（`contains`）**：
   自待測點 $(x_0, y_0)$ 向 $+X$ 方向發射水平射線，統計與多邊形邊段的交點數：
   $$\text{crossings} = \sum_{i=0}^{n-1} \mathbb{I}\left( \left((y_i > y_0) \neq (y_{i+1} > y_0)\right) \land \left(x_0 < x_i + \frac{y_0 - y_i}{y_{i+1} - y_i}(x_{i+1} - x_i)\right) \right)$$
   當 $\text{crossings} \pmod 2 = 1$ 時，嚴格判定點位於陸地內部。
2. **線段跨島判定（`segCrossesLand`）**：
   檢查兩點間連線是否與海岸線任意邊相交，或兩端點/中點是否落於陸地內。
3. **水域可用段截取（`waterPortion`）**：
   若目標線段自水域出發並延伸至陸地，演算法自動計算射線與海岸線的第一個交點，並向水域側回縮安全餘裕 $d_{\text{standoff}}$（如 10m），截取合法的純水域航段。

### 2. 近岸安全守護與自救程序（`pLandGuard`）

```
                     【無人船本機導航 NAV_X, NAV_Y, NAV_SPEED】
                                       │
                                       ▼
                             ┌───────────────────┐
                             │    pLandGuard     │
                             │  (加載 LandModel) │
                             └─────────┬─────────┘
                                       │
          ┌────────────────────────────┼────────────────────────────┐
          ▼                            ▼                            ▼
  [ 離岸即時監控 ]              [ 近岸主動限速 ]              [ 觸礁自救脫困 ]
  發布 LAND_CLEARANCE           當 Clearance < 20m           當 Clearance <= 0m (進島)
  (每秒更新至最近陸地距離)       觸發 LAND_SLOW = true        發布 LAND_BREACH = true
                                Helm 主動降低巡航速           發布 LAND_ESCAPE_PT = (x,y)
                                (為舵機爭取迴轉半徑)          (導引至歷史開闊水域麵包屑)
```

#### 🛡️ 麵包屑自救原理（Breadcrumb Recovery）
當無人船因極端海況或被逼迫而進入陸地邊界時，傳統避碰行為因「已在障礙物內部」而失效沉默。`pLandGuard` 持續維護歷史安全航跡點隊列（Breadcrumbs）：
- 脫困點並非選擇「幾何最近的水域」（該方向可能隔著狹窄沙洲、越走越深）；
- 而是選擇**「本船進入該區域前最後一個處於完全開闊水域的歷史點」**，確保路徑具備 100% 物理可達性，導引子船原路退回安全海域。

### 3. 全域協同規劃器之海圖深度融合 (`pTargetCoordinator`)

#### 🗺️ A. 逃逸扇區地形過濾（Exit Bearings Evaluation）
母船協調器在接戰時，每秒對目標前進方向周圍 36 個方位角（每 $10^\circ$ 一檔）進行步進射線探測：
$$\text{ExitDistance}(\theta) = \int_0^{D_{\max}} \mathbb{I}\left( \text{segCrossesLand} \lor \text{distToLand} < d_{\text{standoff}} \right)$$
- 若某方位角之射線撞擊島嶼或通過窄於 $d_{\text{standoff}}$（10m）的淺灘，該出口直接判定無效（$\text{Cost} = -1$）。
- **戰術價值**：當入侵目標逃入海灣或死胡同水域時，協調器即時掌握**「陸地已封鎖大部分逃逸扇區」**，包夾子船無須盲目展開大開角防線，而是直接卡住海灣出口，以最小機動達成封閉式圍捕。

#### 🌊 B. 站位點安全水域投影（`pullStationToWater`）
- 若幾何計算出的 Lead 阻擋點或 Denier 側翼點剛好落在島嶼內部，系統自動調用 `m_land.waterPortion()`，沿著目標與站位點的射線將座標**向目標側回拉至安全水域（離岸 10m）**。
- 保證阻擋臂幾何朝向不變，徹底杜絕子船開往陸地灘頭卡死的現象。

### 4. 模擬器防穿透步長防護機制（`uSimMarineV22` Stall Guard）

#### 🛑 主機延遲引發的「穿島漏洞」
在長時間或多進程密集測試中，若主機 CPU 出現數秒卡頓（Stall），模擬器在恢復後計算時間差 $\Delta t = t_{\text{curr}} - t_{\text{prev}} = 10\text{ s}$。以 $2.5\text{ m/s}$ 航速計算，單步積分將使船隻瞬間前進 **25 公尺**，直接跨過寬度僅 15 公尺的島嶼，導致避碰行為完全來不及介入。

#### 💡 `max_time_step` 防護邏輯
在 [`USM_Model.cpp`](file:///l:/home/yoei/moos-ivp/ivp/src/uSimMarineV22/USM_Model.cpp) 中引入步長截斷：
```cpp
if((m_max_time_step > 0) && (delta_time > m_max_time_step)) {
  double skipped = delta_time - m_max_time_step;
  delta_time = m_max_time_step;
  m_stall_count++;
  m_stall_skipped += skipped;
  m_record.setTimeStamp(m_record.getTimeStamp() + skipped);
}
```
- **核心保證**：單次物理推進時長絕不超過 `max_time_step`（預設 0.25s），即使主機暫停 1 分鐘，恢復後模擬世界亦嚴格按安全微小步長推進，絕不發生單幀瞬移穿島。
