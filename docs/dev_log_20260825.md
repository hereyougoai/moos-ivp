## 一、 8/25 研發背景與核心升級總覽

本日研發聚焦於徹底解決 **m_shield_demo（Shield AI 多無人船協同搜索、包夾與驅逐防衛系統）** 在真實模擬與逼退演練中所暴露的關鍵工程與戰術瓶頸：

1. **地面固定式阻擋站位演算法（Ground-Fixed Blocking Stations）**：
   - 捨棄舊有隨目標動態旋轉的相對夾角跟隨，改於目標前進航線上投影固定的地面攔截點，由主攔截船（Lead）與側翼封堵船（Denier）形成實體路障。
2. **自適應壓迫間距收縮（Adaptive Offset Narrowing）**：
   - 若目標在時限內未產生避碰轉向反應，系統自動步進式收縮橫向封堵間距，逐級提高對目標船 Helm 的避碰壓迫力。
3. **航渡可行性驗證與站位鎖定機制（Transit Feasibility & Station Hold Lock）**：
   - 計算子船實際航速與抵達時間，引入航渡保護鎖定（Transit Hold），避免站位發布頻率遠高於子船機動能力導致的無效迂迴。
4. **新增速度即時調控介面（USV Speed & Target Speed Menus）**：
   - 於 Shoreside 圖台（pMarineViewer）新增 **Action/USV Speed** 與 **Action/Target Speed** 雙向階層式即時調速下拉選單，支援在演練過程中一鍵動態切換子船（1.0~4.0 m/s）與目標船（0.5~3.0 m/s）航速。
5. **目標 Helm 客觀函數離線評估工具與批次測試套件（ench.py / ench.sh）**：
   - 建立離線重構目標船 Helm 避碰客觀函數之數學模型，定義 **PUSH 壓迫力指標**，並實作自動化多回合無頭模擬（Headless Benchmark）。

### 2. 地面固定式阻擋站位演算法（Ground-Fixed Blocking Stations）

#### 🛑 傳統動態夾角追隨（Trail Arc）的失效根源
在動態夾角模式中，站位點是相對於目標船動態旋轉的相對座標。目標船的 BHV_AvoidCollision 在評估其當前航向時，子船由於位處側後方，其 CPA 遠大於避碰啟動門檻，導致目標船在原前進航向上的效用值仍為滿分（100 分），目標船無須做出任何避讓（外觀看似兩艘子船在為入侵者「護航」）。

#### 💡 演算法數學推導與幾何模型 (ssignAndPostBlock)

`
                          目標航向正前方 (Heading Vector u_hdg)
                                            ▲
                                            │
                        [Lead 主阻擋站位]   │
                         x_lead, y_lead     │ (前向提前量 block_lead = 40m)
                               *            │
                                \           │
                                 \          │
    (側向橫移 block_offset = 14m) \         │
                                   \        │
                                    *───────┼────────► (側向法向量 u_lateral)
                             [Denier 側翼站位]│
                              x_denier, y_denier
                                            │
                                            │
                                     [目標 Target]
                                      x_tgt, y_tgt
`

1. **單位向量建立**：
   根據目標船目前航向 $\theta_{\text{tgt}}$（單位：弧度）：
   \mathbf{u}_{\text{hdg}} = \begin{bmatrix} \sin\theta_{\text{tgt}} \\ \cos\theta_{\text{tgt}} \end{bmatrix}, \quad \mathbf{u}_{\text{lateral}} = \text{side} \times \begin{bmatrix} \cos\theta_{\text{tgt}} \\ -\sin\theta_{\text{tgt}} \end{bmatrix}
   其中 $\text{side} \in \{+1 (\text{右舷}), -1 (\text{左舷})\}$，由最優逃逸方向決定。
2. **主攔截船站位點計算（Lead Station）**：
   在目標前進航線前方 {\text{lead}} = 40\text{ m}$、側向偏移 {\text{offset}} = 14\text{ m}$ 處建立固定地面座標：
   \mathbf{P}_{\text{lead}} = \mathbf{P}_{\text{tgt}} + L_{\text{lead}} \cdot \mathbf{u}_{\text{hdg}} + d_{\text{offset}} \cdot \mathbf{u}_{\text{lateral}}
3. **側翼封堵船站位點計算（Denier Station）**：
   側翼船部署於前向縮減比例 $\text{lead2} = 0.5$（即 \text{ m}$ 前方）、側向外擴 $\text{span} = 18\text{ m}$（即 \text{ m}$ 側向）：
   \mathbf{P}_{\text{denier}} = \mathbf{P}_{\text{tgt}} + (L_{\text{lead}} \cdot \text{lead2}) \cdot \mathbf{u}_{\text{hdg}} + (d_{\text{offset}} + \text{span}) \cdot \mathbf{u}_{\text{lateral}}
4. **地面座標下發**：
   計算出的站位點以靜態航點形式發布至子船 MOOSDB：
   `ini
   WPT_UPDATE_ABE = points = pts={x_lead, y_lead} # transit_speed = 3.0
   WPT_UPDATE_BEN = points = pts={x_denier, y_denier} # transit_speed = 3.0
   `
5. **物理逼退機制**：
   當目標船持續前進時，正前方偵測到靜態存在的子船，其 BHV_AvoidCollision 的 CPA 預測降至 0m，原航向效用驟降為 0，迫使目標船做出 $> 45^\circ$ 的大角度轉向撤離。

在 [TargetCoordinator.cpp](file:///l:/home/yoei/moos-ivp/ivp/src/pTargetCoordinator/TargetCoordinator.cpp) 之 updateAdaptiveOffset() 實作階梯式增壓機制：

### 4. 航渡可行性驗證與站位保護鎖定（Transit Feasibility & Station Hold）

#### 🔍 歷史量測痛點
在多船非同步通訊中，母船協調器以 2Hz 頻率運算。若目標航向有微小擾動，阻擋點座標每 2~3 秒便位移數十公尺。然而子船以 3.0 m/s 航速航渡至 30m 外的目標點需要約 **10 秒**。換言之，**站位更新頻率是子船機動響應極限的 3~4 倍**，導致子船在半途頻繁換向打轉。

#### 🛡️ 實作解法 (lockTransitHold)
1. **航渡耗時精準計算**：
   T_{\text{transit}} = \frac{\|\mathbf{P}_{\text{usv}} - \mathbf{P}_{\text{station}}\|}{V_{\text{usv}}}
2. **站位鎖定時間（Hold Duration）**：
   T_{\text{hold}} = \min(T_{\text{transit}} \times \text{transit\_frac}, \text{transit\_cap})
   - lock_transit_frac = 1.0（全額覆蓋航渡時間）
   - lock_transit_cap = 8.0s（單次站位鎖定上限時間）
3. **效果**：站位一旦發布，系統保證在 {\text{hold}}$ 內嚴禁隨意更換座標點，確保子船能執行直線全速衝刺並在關鍵節點確實就位。

### 5. 車隊內部互避行為重構（Vehicle Mutual Avoidance Refactoring）

* **重構決策**：
  將子船之間的互避模組由 BHV_AvdColregsV22 改回對稱式 BHV_AvoidCollision。
* **技術原因**：
  BHV_AvdColregsV22 內部依國際海事規則嚴格區分 Rule 14（對遇雙方右轉）與 Rule 15（讓路船右轉、直航船保向保速）。但在阻擋任務中，兩艘子船是作為一個**戰術整體（Interdiction Pair）**，其任務是在空間中共同構建防線。若套用 COLREGS 角色指派，會出現「右側子船被強制認定為直航船而禁止向左靠攏封堵，左側子船被認定為讓路船而大幅繞遠」的幾何扭曲現象。改用對稱式 BHV_AvoidCollision 保證兩船以相同 CPA 權重協同卡位。

### 6. 離線客觀函數評估工具（ench.py）與 PUSH 壓迫力指標

#### 📊 數學原理
ench.py 透過解析 ALog 檔案，在每一時間戳離線重構目標船 Helm 所求解的客觀函數：
\text{PUSH}(t) = \max_{c, s} U_{\text{avoid}}(c, s) - U_{\text{avoid}}(\text{Heading}_{\text{current}}, \text{Speed}_{\text{current}})
其中避碰效用函數 {\text{avoid}}(\text{cpa})$ 定義為：
U_{\text{avoid}}(\text{cpa}) = \begin{cases} 0 & \text{if } \text{cpa} \le 12\text{ m} \\ \frac{\text{cpa} - 12}{25 - 12} \times 100 & \text{if } 12\text{ m} < \text{cpa} < 25\text{ m} \\ 100 & \text{if } \text{cpa} \ge 25\text{ m} \end{cases}
- **$\text{PUSH} = 0$**：子船未對目標前進方向構成任何威脅（直行即為 100 分）。
- **$\text{PUSH} > 0$**：直行效用受損，目標必須偏航以獲取更高避碰效用。
- **評估指標**：
  1. **平均壓迫力（Mean PUSH）**：在接觸期間的平均壓迫強度。
  2. **有效壓迫時間比（Push Duty Cycle）**：$\text{PUSH} > 5.0$ 的時間佔總接觸時間的百分比。
